# REVIEW.md

Review of the starter `app/main.py`. Each row is one defect; all of them are fixed in the final `app/main.py`.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` | Always returns `{"status":"ok"}` without touching MongoDB. | Stop MongoDB, call `GET /health`: still 200 instead of 503. | `client.admin.command("ping")`; any `PyMongoError` becomes 503. |
| 2 | `MongoClient(...)` | `tz_aware` is off, so PyMongo returns naive datetimes. Subtracting them from aware values raises `TypeError` (500), and naive/aware mixes silently shift times. | Punch out on a record, subtract stored `punch_in` from an aware `punch_out`: crash. | `tz_aware=True`; every instant is an aware UTC datetime, converted to epoch ms only at the API boundary. |
| 3 | `compute_late_minutes` | Builds the shift start with `punch_in.replace(hour=...)` in the punch's own time zone (UTC / server-local) instead of IST. | An IST employee punching 09:41 IST (04:11 UTC) is compared with 09:30 *UTC*: reported ~-5 h, so never late. | Shift start is built as an IST datetime for the attendance date (`at_ist`). |
| 4 | `compute_late_minutes` | `int(seconds/60)` is applied before `> 10`, so 09:40:01 gives 10 minutes and is treated as "not late" (`10 > 10` is false). Grace must be strictly more than 10:00. | Shift 09:30: punch 09:40:01 must return 10, starter returns 0. | Compare in seconds (`seconds > 600`), then `seconds // 60`. |
| 5 | `compute_late_minutes` / `punch_in` | Uses the punch-in's own calendar date, ignoring overnight shifts (R1). | Shift 22:00-06:00, punch 02:00 IST on the 8th must belong to the 7th and be 240 min late. | `attendance_date()` implements R1; lateness is measured from the shift start of that attendance date. |
| 6 | `compute_work_hours` | `round()` is banker's rounding on a float; R4 needs half-up. | 18 seconds = 0.005 h must give 0.01. | `Decimal(seconds) / Decimal(3600)` quantized with `ROUND_HALF_UP`. |
| 7 | `compute_overtime` | Returns any positive minutes; R3 says overtime counts only if at least 30 minutes. | Shift end 18:30, punch-out 18:40: starter returns 10, expected 0. | Floor to whole minutes, return 0 below 30. |
| 8 | `compute_overtime` | Uses the record date for the end of an overnight shift; the shift ends the next day. Also `punch_out` is naive (see #2) so the subtraction fails. | Shift 22:00-06:00, punch-out 06:40 next day must give 40; starter gives a huge negative / crash. | `shift_end` date is advanced by one day when `shift_end <= shift_start`. |
| 9 | `EmployeeIn`, `PunchInIn` | No validation: any `emp_code`, malformed email / dates / shift times, equal shifts, any `status` string (even `ABSENT` or `"banana"`), floats and second-looking timestamps accepted. | `POST /employees` with `emp_code:"x"` returns 201; punch-in with `status:"ABSENT"` returns 201. | Pydantic constraints (patterns, lengths, `Literal` statuses, strict integer epoch ms in range, `shift_start != shift_end`, real calendar date). |
| 10 | `create_employee` | Check-then-insert: two parallel requests can both pass the `find_one`. No unique index exists. | 10 parallel creates with the same `emp_code` give several 201. | Unique index on `emp_code`; `insert_one` and map `DuplicateKeyError` to 409. |
| 11 | `create_employee` | `created_at = datetime.now()` is naive server-local time and is returned as a datetime, not epoch ms. | Response `created_at` is an ISO string in local time. | Store a UTC datetime, return epoch milliseconds. |
| 12 | `list_employees` | `skip = page * page_size` skips the first page. | `page=1` never returns the first employees. | `(page - 1) * page_size`. |
| 13 | `list_employees` | `total` counts the whole collection, not the filtered set; no sort; `page=0`, negative, or `page_size=100000` are accepted. | `?department=Eng` returns `total` = all employees. | `count_documents(filter)`, sort by `emp_code`, `page >= 1`, `1 <= page_size <= 100`. |
| 14 | `punch_in` | Unknown employee: `emp` is `None`, `emp["shift_start"]` raises `TypeError`, a 500. | `POST /attendance/punch-in {"emp_code":"EMP9999"}`. | Return 404 before doing anything else. |
| 15 | `punch_in` | `datetime.fromtimestamp(ms / 1000)` uses server-local time and a float; `if body.punched_at` treats `0` as missing; sub-seconds are not truncated (R1). | Run the server in a non-UTC zone: stored instants are off; `punched_at=…999` keeps milliseconds. | Integer arithmetic from epoch ms in UTC, floored to whole seconds. |
| 16 | `punch_in` | The attendance `date` is the server's local date, not the IST date (R1). | Punch at 23:30 IST on a UTC server: record lands on the wrong day. | Date computed in IST by `attendance_date()`. |
| 17 | `punch_in` | Same check-then-insert race as #10, for `(emp_code, date)`. | Parallel identical punch-ins: several 201. | Unique index `(emp_code, date)`; exactly one insert wins, the rest get `DuplicateKeyError` -> 409. |
| 18 | `punch_in`, `list_attendance` | Responses expose MongoDB's `_id` as `id` (the contract forbids it) and return BSON datetimes instead of epoch ms. | Look at the JSON of any attendance response. | `serialize_record()` builds the response explicitly: no `_id`, instants as epoch ms, legacy fields defaulted. |
| 19 | `list_attendance` | Loads every matching document into memory, sorts and slices in Python, and `total` is `len(docs)`. No `emp_code` tie-break in the sort. | 100,000 records: slow and memory-heavy; two records on the same date come back in arbitrary order. | Database-side sort `(date desc, emp_code asc)`, `skip`, `limit`, plus `count_documents`, all backed by indexes. |
| 20 | `list_attendance` | No validation of `date_from`/`date_to`/`status`/paging; `date_from > date_to` is not a 422; an empty `emp_code=` is silently ignored (`if emp_code:`). | `?date_from=2026-07-09&date_to=2026-07-01` returns 200. | Dates parsed as real dates, `Literal` status, range check -> 422, filters tested with `is not None`. |
| 21 | whole file | No indexes at all, so every query is a collection scan. | `explain` shows COLLSCAN; the unique guarantees above are impossible. | `ensure_indexes()` at startup (idempotent) for every access path; see DECISIONS.md. |

**Looked at and considered fine:** `load_dotenv()` (does not override real environment variables, as required); the `IST` constant; the `201` status codes; reading `MONGO_URI`/`MONGO_DB` from the environment (the localhost default is only a fallback for local runs); `model_dump()` for building the document. Also fine in principle: measuring elapsed *seconds* in `compute_work_hours` (only the rounding was wrong), and the exact, case-sensitive department filter (the contract asks for exactly that).
